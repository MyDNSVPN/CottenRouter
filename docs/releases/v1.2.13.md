## ✨ Highlights

- **SlipGate installs through CottenRouter on fresh servers again.** It used to fail within seconds with `exit status 1`.
- **The router stays up.** An interrupted install now rolls back and restarts it, and a domain conflict is caught before anything stops.
- **Every backend stays behind the router.** CottenDNS can no longer be reached directly over public IPv6, and StormDNS no longer blocks the server's outgoing DNS-over-TCP.
- **No lost queries under heavy bursts,** and less work per query.

## 🚀 Upgrade

Run the installer again. It upgrades in place and keeps your routes, backends, and settings:

```bash
curl -fsSL https://raw.githubusercontent.com/TaJirax/CottenRouter/main/scripts/install.sh | sudo bash
```

Install exactly this release:

```bash
curl -fsSL https://raw.githubusercontent.com/TaJirax/CottenRouter/main/scripts/install.sh \
  | sudo bash -s -- --version=v1.2.13
```

> [!IMPORTANT]
> **After upgrading, re-save each backend once.** The CottenDNS and StormDNS fixes apply the next time a backend is installed or its settings are saved. Run `sudo cottenrouter tui`, open **Install**, select the backend, press **Enter**, and save without changes.

> [!NOTE]
> **Advanced settings for CottenDNS** now refuse a configuration that leaves UDP open on public IPv6. Set `UDP_IPV6_HOST = "::1"`, or save the common settings once as described above.

## 🚪 SlipGate

| Change | What it fixes |
|---|---|
| **Installs on fresh servers** | On any server that had never run SlipGate, installing it through CottenRouter failed within seconds with `exit status 1`. |
| **Slipstream tunnels no longer stop the router** | The router needed a certificate file only root can read, so it refused to start. The certificate fingerprint is now stored in the router config. |
| **No router restart loops during install** | SlipGate's own DNS router is turned off before its tunnels restart, so it can no longer hold port `53` while CottenRouter starts. |
| **Tunnel port clashes are refused** | A SlipGate tunnel port already used by another backend used to route traffic to the wrong place. The error now names the tunnel, the port, and the route that owns it. |
| **Fresh Ubuntu and Debian installs** | The system's local DNS stub no longer blocks the install, and SlipGate's setup no longer opens twice. |

## 🛡️ Reliability and security

| Change | What it fixes |
|---|---|
| **Interrupted installs roll back** | Pressing <kbd>Ctrl</kbd>+<kbd>C</kbd> at an installer prompt, or losing the SSH connection, used to leave the router stopped until someone noticed. Install, configure, remove, and advanced settings now undo their changes and restart it. |
| **Domain conflicts are caught first** | Using a domain another backend already owns used to run the whole upstream installer, with DNS down, before failing. It is now refused before anything stops. |
| **CottenDNS stays private on IPv6** | Current CottenDNS releases listen for UDP on every public IPv6 address by default, which let clients bypass the router. That listener is now kept on loopback. |
| **StormDNS no longer blocks outgoing DNS-over-TCP** | StormDNS installs a boot service that rejects every outgoing TCP connection to port `53`. That breaks the server's own DNS lookups and conflicts with CottenDNS. CottenRouter now disables it and removes its rules. |

## ⚡ Performance

The router now asks the kernel for 4 MiB UDP socket buffers instead of the ~256 KiB default, so bursts are queued instead of dropped. Route lookups and statistics no longer allocate on every packet.

Measured on a 1 vCPU / 4 GB Ubuntu 24.04 VPS against the routes of a full five-backend install:

| Measurement | v1.2.10 | v1.2.13 |
|---|---:|---:|
| Queries lost, 512 concurrent clients | 1.4% | **0%** |
| Answered queries per second, 512 clients | 16,800–18,200 | **21,600–22,200** |
| Route lookup time | 219 ns | **81 ns** |
| Allocations per forwarded query | 29 · 703 B | **17 · 380 B** |
| Router memory at 512 clients | 23 MiB | 26 MiB |

At normal load, throughput and latency are unchanged.

> [!TIP]
> The larger buffers need `net.core.rmem_max` of at least 4 MiB. Stock Ubuntu allows about 208 KiB. On busy servers, raise it and make it persistent:
>
> ```bash
> printf 'net.core.rmem_max = 8388608\nnet.core.wmem_max = 8388608\n' | sudo tee /etc/sysctl.d/60-cottenrouter-udp.conf
> sudo sysctl --system && sudo systemctl restart cottenrouter
> ```

## 🧭 Control deck, installer, and uninstaller

| Change | What it fixes |
|---|---|
| **The TUI shows the real error** | Failures used to appear only as `exit status 1`. The notice now shows the actual reason, for example which domain is already in use. |
| **No false warnings on fresh installs** | Every new install warned that *a test DNS query returned no answer* and that *firewall management is unsupported*, even on healthy servers with no firewall. |
| **A full purge leaves a clean server** | `cottenrouter-uninstall --purge --purge-backends --confirm CottenRouter` used to start SlipGate's installer instead of removing it, and left SlipGate's binaries, users, and DNS setting behind. It now removes SlipGate and StormDNS's filter completely. |
| **No hangs on stuck processes** | The TUI and the SlipGate step of a full purge can no longer wait forever on a background process or an unexpected prompt. |

## 🧪 How it was tested

Everything was verified on a fresh Ubuntu 24.04 VPS:

- All five backends (SlipGate, CottenDNS, MasterDnsVPN, StormDNS, thefeed) installed through the TUI
- Every route checked over IPv4 and IPv6, UDP and TCP, with unrouted names confirmed dropped
- A real dnstt tunnel carrying HTTPS through the public IP, before and after reboots
- Interrupted installs, a full purge back to a clean server, and a fresh install with the one-line command
- Go tests with the race detector, and a concurrent load test comparing v1.2.10 and v1.2.13

**Not yet covered:** VayDNS, NaiveProxy, StunTLS, DoT/DoH, and SlipGate's Advanced menu.

> [!NOTE]
> The default per-IP limit is 2,000 queries/s with bursts to 4,000. A busy public resolver can reach it; add its ranges to `trusted_resolver_cidrs` in the router config if needed.
