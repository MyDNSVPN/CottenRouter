# CottenRouter v1.2.18

This release adds two independent Soar backends and makes guided installation
work across all seven projects in an ordinary terminal.

## Changes

- **Soar** builds verified official Lantern source. **Soar 2.2** installs the
  verified WhiteDNS standalone bundle using its older Lantern **v0.2.2** engine.
  They have separate services, keys, data and private ports and can run together.
- The TUI fits 80×24 terminals, validates forms before starting installers,
  supports Tab/Shift+Tab navigation, reports batch progress and keeps key results
  visible. All seven projects appear in the guided queue.
- `install.sh --local-source=PATH` builds the exact local checkout, including
  uncommitted changes, with matching units and helper scripts.
- Fixed MasterDnsVPN's native service startup flags and SlipGate's public
  resolver configuration permissions under a restrictive umask.
- Added CottenDNS development-mode CottenMax public-key output to CLI/TUI key
  results. Shared secrets remain hidden by default and signing seeds are not read.
- Improved routing isolation, backend ownership checks, rollback, and Docker
  runtime packaging. Release artifacts include Linux amd64/arm64 binaries and
  SHA-256 checksums; Docker publication follows successful release validation.

## Validation

Ubuntu 24.04 under WSL2 passed all seven actual installers through the real TUI,
concurrent shared-port DNS routing, both Soar encrypted HTTP tunnels, upgrades,
restart recovery, identity preservation, safe uninstall and full purge.
Go tests, race detection, static analysis, shell regressions and Docker forwarding
were also checked.

The exact local CottenDNS checkout at `48d6c81d` with its uncommitted CottenMax
changes was built and checked separately: full unit tests/static analysis,
legacy encrypted application traffic through the router under clean/simulated
resolvers, CottenMax over routed UDP/TCP, and direct IPv4/IPv6 UDP/TCP/DoT.
These tests do not publish the separate CottenDNS checkout. The normal native
installer continues to select its published upstream release.

Public DNS delegation, certificate-authority issuance and optional SlipGate
WARP/transports need deployment-specific validation. See the
[WSL validation record](../../tests/systemd/README.md) and
[local CottenDNS compatibility gate](../../tests/integration/cottendns/README.md).

## Install or upgrade

```bash
curl -fsSL https://raw.githubusercontent.com/TaJirax/CottenRouter/main/scripts/install.sh \
  | sudo bash -s -- --version=v1.2.18
sudo cottenrouter tui
```

Select projects with Space and press `i` to install. Give the two Soar backends
different delegated zones. Soar 2.2 currently requires the WhiteDNS amd64 bundle.
